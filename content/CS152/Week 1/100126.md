## CFG and Parsing

Parsing identifies the sentence of the token stream and produce the AST (abstract syntax tree). Afterwards, analysis makes sense of this tree.

### Parsing: Finding Syntactic Structure

![[Screenshot 2026-10-01 at 6.50.24 PM.png]]

- Input: stream of tokens (by lexer)
- Output: AST
- Strategy:
	- parse token stream to traverse "concrete" syntax (parsing tree)
	- during traversal, build a tree representing the "abstract" syntax (AST)
- AST: AST(a+b) = AST((a+(b))) = AST ((a) + (b))
![[Screenshot 2026-10-01 at 6.52.18 PM.png]]

We need to answer three questions when considering parsing:
- How to specify the syntax structures in a language?
- How to represent these syntax structures?
- How to recognize these syntax structures?

#### Specifying Language Syntax

*How to describe language syntax precisely and conveniently?*
Last time we described tokens using regex
- easy to implement, efficient DFA representation
- Why not use regular expressions on tokens to specify programming language syntax
	- DFA's have only finite # of states
	- Can't count
	- Need a stack to keep track of "(" and ")"
