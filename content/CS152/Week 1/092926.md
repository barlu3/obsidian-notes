### Compilation in a Nutshell

#### Lexical Analysis

Take the character stream (source code) into tokens; data type representing "chunks" of text:
- identifiers: a yll elsex \_100 
- keywords: if else while
- integers: 2 200 -500
- floating point: 2.0 3.2 0.9
- symbols: + \* - / %
- strings: "Hello"
- comments: //comment

##### Token Specification

In regex, keywords can simply be matched to the literal string, i.e.
	`IF = "if"`
	`PLUS = "+"`

Identifiers begin with a letter and contains only letters, digits, and \_
	`letter = [a-zA-Z]
	`digit = [0-9]
	`identifier = letter(letter|digit|_)*`

For numbers:
	`nat = [0-9]+`
	`signedNat = [+-]? nat`
	`decimalNum = signedNat \. nat`
	`scientificNum = decimalNum E signedNat`
	`number = signedNat (\. nat)? (E signedNat)?`

For comments (pseudo-token for the purpose of this class):
	C/C++: `//[^\n]*`
	Pascal: `\{^\{\}]*\}` -> {pascal comment}

Token specification may contain ambiguities; existing multiple ways to interpret the same string:
- "if" IF vs "if" identifier (choose IF)
- "cs152" identifier vs "cs" "152" identifier and num (choose longer substring)

Token delimiters are character sthat imply a longer string cannot be a token:
- White space, comments, "=", etc.
- Not all tokens need delimiters to recognize ("\[")
- Ends a token, not part of it (not consumed but examined)
