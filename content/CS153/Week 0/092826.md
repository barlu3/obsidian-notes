### Phase 0 

- In the beginning, OS is just runtime libraries (routines)
	- piece of code used/sharable by many programs
	- abstraction: reuse magic to talk to physical device
	- avoid bugs
- user scheduled an exclusive time where they would use the machine
- UI was switches and lights, eventually punched tape and cards
	- less bugs as a result of the switch

### Phase 1 (batch systems)

- Computers expensive; people cheap
	- use computers efficiently - move people away from machine
- OS became a program loader
	- loads a job, runs it, outputs result, moves on to next job
	- more efficient use of hardware but harder to debug
		- less bugs doe

### Advances in OS in this period

- SPOOLING/Multiprogramming
	- Simultaneous Peripheral Operations On-Line (SPOOL)
		- Non-blocking tasks
		- copy document to printer buffer so printer can work while CPU moves to something else
	- Hardware provided memory support
	- Scheduling
	- OS must manage interactions between concurrent things

### Phase 1 (problems)

- Utilization is low (one job at a time)
- No protection between jobs
- Scheduling
- Coordinating concurrent activities
- People time being wasted
- OS didn't really work
